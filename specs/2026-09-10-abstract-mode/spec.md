# Spec: claude-supervisor abstract 模式 — 抽象提炼任务监工

> 分支：`feat/v3-multi-supervisor`
> 依据：2026-09-10 用户需求（"抽象提炼，提纲挈领的从更高层次抽象"）+ 需求裁决（形态=第四模式全套监工；输入=混合面；验收=两件套）
> 状态：已实施（2026-09-10，含两轮 subagent CR 修复）；真机冒烟未做

## 1. 背景与问题

v3 已有三模式：绿地（从零开发）、rework（老项目修补）、research（调研/探索）。三类任务的共同假设是**产出方向为发散**——从问题出发去世界找证据（research）或从目标出发写代码（绿地/rework）。第四类高频真实场景方向相反：**输入是一堆现成材料，产出是支配它们的高层结构**。两个用户实例：

1. 几篇调研报告/文章 → 提纲挈领提炼当前系统的根因问题；
2. 零零碎碎十几处代码修改 → 从项目视角提炼共性、反推作者意图（"这些改动共同想达到什么目标"）。

这类**收敛/综合任务**直接套用 research 模式会暴露四个缺口：

1. **验收锚点错位**：research 是"逐问有答案+置信度"（问题↔章节对账）；抽象任务的对账方向是"材料↔命题"——**任何一件输入材料没被任何命题解释到，要么补命题要么显式声明为反例**（覆盖矩阵），research 的对账条款覆盖不了这个方向。
2. **证据方向相反**：research 的证据在材料外（要去查库上网）；抽象任务的证据在材料内（要回指）——最忌讳跑出去查新东西扩大输入面。research 的信息源审查/检索策略条款在这里不仅无用，还会误导。
3. **失败模式不同**：research 最怕伪证；抽象最怕**空话化**（不可证伪的正确废话）与**叙事强制**（把散乱强行拧成一个故事，忽视多因现实），还有独有的**缺席信号**意识——材料里反复缺席的东西（diff 里没动测试、报告集里回避的话题）本身就是最高层信号，只看"有什么"提炼不出"没什么"。
4. **产出粒度不同**：research 是逐章生产（dev-N = 每章一个调研单元）；抽象是"一轮出稿、多轮对抗返工"的形状，天然没有逐章生产单元。

v3 核心资产（身份/账本/四层中断防御/巡检/watchdog/OODA/三层回答防火墙/红线）继续全部模式无关复用。选择第四模式全套监工（而非轻量单会话）的裁决依据：抽象最容易自我感觉良好，空话与叙事强制靠作者自查几乎查不出来——**生成与对抗审查分属两个会话（不同上下文）才有真对抗**，监工机制的全部成本换的正是这个。

## 2. 目标

1. 新增 `/abstract` 命令（抽象提炼模式），复用「模式层 + `_core-supervisor.md`」拼接架构；
2. abstract 特有机制：ingest 材料盘点（逐件压缩+锚点清单+**输入面锁死**）、distill 命题草稿（M 条命题+回指锚点+置信度+覆盖矩阵）、refine-N 对抗返工轮（监工审查驱动定向返工，非逐章生产）；
3. 验收两件套（用户裁决）：**覆盖对账**（逐材料被解释）+ **回指锚点**（每条命题必附文件:行/commit hash/文档段落）强制；**替代解释**（至少生成一个并说明为何不选）做建议不做强制；
4. 绿地/rework/research 模式层零改动；core 的改动限于两处：registry `--mode` 枚举补 abstract（P2-A 修复时硬编码的枚举）+ 状态机进入/推进条款参数化（执行阶段语义以模式层声明为准，dev-N 骨架为默认——第四模式的 refine-N 无 total_phases，subagent CR P1 实证原状态机无法进入/收尾 refine-N）——四产物同步重拼，拼接结构断言全过。

## 3. 非目标

- 不做任务类型自动判定（用户显式选命令，沿用既有哲学）；
- 不改 worker.md / hook / watchdog（零代码改动边界：抽象差异全部在模式层声明；worker 协议本就模式无关）；
- 不做报告模板引擎/渲染（markdown 落盘即交付）；
- 不做命题条数上限强制（≤7 条逼真提炼是 hard 档裁决时未选项，写入 DoD 会与"两件套"裁决冲突——仅在 distill 审查时以观察形式提示）。

## 4. 设计决策

- **状态机**：`<ingest|distill|refine-N>`。ingest 对应 research scope 的位置（把一堆材料盘点成可对账的清单）；distill 对应 survey 的位置（命题草稿 = 监工对抗审查的对象）；refine-N 替代 dev-N——每轮针对审查缺陷定向返工，不是逐章生产。复用 research 的"前置阶段质询上限两轮、与 Loop Guard 独立计数"。
- **输入面锁死（ingest 定稿后不得引入新材料）**：抽象的证据在材料内，输入面一漂移，覆盖对账就失去意义（对一池不断进水的水做覆盖矩阵）。与 research 的范围纪律方向相反：那边锁产出（diff ⊆ 报告目录），这边锁输入。唯一豁免：监工锚点抽查时打开材料本身核对，不算引入新材料。
- **命题两分法**：命题分两类标注——`材料内模式`（可直接回指到 ≥1 处具体锚点的共性/模式）与`意图/归因推断`（"作者想达到什么""根因是什么"——本质是推断，必须显式标注推断性质与置信度）。这是防止揣测当事实的关键条款；两件套的"回指锚点"对前者是硬要求（锚点必填），对后者要求标注"由哪些锚点支撑"的推导链。
- **缺席信号义务**：distill 必须显式回答"材料里反复缺席的是什么"（未改的测试、回避的话题、始终未出现的信息源）——缺席不自动成为命题，但必须进未决/观察清单，禁止只看"有什么"。
- **锚点抽查（监工，机械回放纪律的迁移）**：每轮审查你亲自打开若干回指锚点，核对命题与材料实际内容相符——锚点指向不存在/内容不符即该命题 REFINE；一条命题的锚点系统性造假 → 整轮 REFINE 重提炼（对齐 research 伪证条款的严肃度）。
- **空话检查（审查必做项，机械判据）**：逐命题自问"这条命题被证伪时会看到什么/用户拿它能做什么"——两者都答不上来的命题判为空话，要求降级为观察或合并进具体命题。替代解释为建议项：distill 产出至少一个替代抽象并说明为何不选为佳，未做不 REFINE。
- **报告落点**：`--out <报告目录>` 缺省 `<project-dir>/docs/abstract/<日期-主题>/`，与 docs/research/ 平级；显式传参启动即校验、缺省定题回填——**整条照抄 research 的 --out 机制**（教训：模式层覆盖通用条款必须整条抄全）。
- **git 语义继承 research**：非 git 目录允许（输入常是文档目录/学城链接，落盘即交付，中断对齐锚用 `--out` 最新落盘产物）；git 仓库内报告照 commit 纪律（trailer `worker: <你的名>, phase: refine-N`，整条抄全含署名与 /rename 时序）。
- **产品代码只读红线继承 research**：worker 产出是报告，对目标仓库产品代码默认只读；范围比对（基线 commit..HEAD ⊆ 报告目录）整条照抄。
- **registry 枚举与状态机参数化**：core 启动步骤 4 命令模板 `<greenfield|rework|research>` 补 `abstract`；状态机「进入执行阶段」与「APPROVE 推进/done」两处改为「执行阶段语义以模式层声明为准，模式层未声明时按 dev-N 骨架」——abstract 模式层随之完整声明 refine-N 的进入（distill APPROVE → refine-1）/推进（REFINE → refine-N+1）/done 判据（一轮零 REFINE 且覆盖对账全过 → done + 照 core 第 4 步收尾），覆盖即完整裁定，不得与 total_phases 混用。四产物重拼。

## 5. 实施清单

- `commands/abstract.md`（模式层，预算 ≤68 行）：frontmatter（description/argument-hint 支持 `--project-dir` `--out`）+ 模式声明（phase 枚举、首阶段指令全文、`--mode abstract`、--out 语义、非 git 允许、长阶段时限）+ worker-facing 五项统一下发（--out 落点/只读红线/锚点与命题格式/非 git 跳 commit 覆盖声明/时间盒与超时上报）+ 前置阶段两节（ingest/distill 质询条款）+ refine-N 特化（锚点抽查/覆盖对账/空话检查/缺席信号/对抗返工）+ abstract 专属纪律（输入面锁死/命题两分法/未决显式化/报告结构/总结披露）；
- `install.sh`：头部注释 `/abstract` 条目 + `splice_command abstract.md` 一行 + 尾部快速开始补示例；
- `_core-supervisor.md`：步骤 4 枚举补 abstract（唯一 core 改动）；
- README：模式清单/抽象提炼章节/命令表/FAQ/文件清单表；
- DESIGN：§12.6 行数预算表更新（改完必须 wc -l 再写数）+ §12 尾 abstract 摘要。

## 6. 测试

install.sh 的拼接结构断言即本模式的安装期回归（断言失败中止安装不留半成品）；重拼后四产物与源逐字节比对（cmp）；核心协议既有测试面（hook/watchdog/registry）全绿证明零代码改动边界未破；模式层是纯 prompt 文本，无可执行面——真机行为留待冒烟验证（另记）。
