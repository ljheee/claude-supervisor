# Spec: 对抗审查模式（/adversarial）

- 状态：spec 待审（2026-09-17）
- 分支：feat/adversarial-review-mode
- 前置依赖：v3 全量（多 supervisor 并存、分片账本、registry 发现层）；abstract 模式的锚点纪律与空话检查判据

## 1. 问题定义

现有四模式覆盖了「产出新东西」（绿地/rework）、「找证据」（research）、「从材料收敛」（abstract），但缺第五类高频任务：**对已有产出做对抗性审查**——审 PR diff、审方案/可行性分析文档、审调研报告。这类任务的痛点不是「没人看」，而是「看的人不对抗」：

- 单会话 review（含 claude 官方 /code-review）是单上下文单视角扫一遍，发现的错误无人挑战（误报混真报一起输出），没看的部分无人知道（无对账），声称的问题无人复核（无锚点验证）。
- 人工找多人审的协调成本高（各自异步、结论散落、视角重复不自知）。
- 方案文档的审查比代码审查更缺工具：论证的自证循环、风险清单避重就轻、假设未标成事实——这些没有现成工具管。

**目标**：一个 supervisor + N 个各持独立视角的 reviewer worker，两轮结构（独立审→交叉攻击），supervisor 合并去重出收敛报告，每条发现带锚点与置信分级。

**非目标**：自动拉起 worker 会话（Claude Code 无跨会话 spawn API，只能推荐数量+引导用户开终端）；替代 CI 静态检查（lint/类型错误走既有工具，本模式只审「工具查不出的判断性问题」）；实时 IDE 内 review（本模式是异步批处理形态）。

## 2. 对抗性的结构来源（设计公理）

**对抗性来自隔离，不来自 prompt 声明**。核心决策一览：

| 决策 | 选择 | 依据 |
|---|---|---|
| 视角载体 | 每 worker 一个视角，独立会话 | 单会话切视角=上下文污染（前一视角结论锚定后一视角）；独立会话是真不知道对方结论 |
| 视角数量 | supervisor 按材料推荐，用户裁决 | 决策前移（见 §4） |
| 轮次结构 | 两轮：独立审→交叉攻击 | 一轮=各说各话；两轮=发现必须被对手回应或撤回 |
| 合并归属 | supervisor 汇聚去重 | 监工本就是消息汇聚点，天然按视角去重、冲突标注 |
| 验证纪律 | 锚点强制+抽查复用 | 复用 research 的 A-C 级抽查与 abstract 的回指锚点 |

**已知取舍**：N 路独立上下文读同一材料 = N 倍 token，这是买真对抗的固定成本；小材料走降级路径（§4 单 worker 多视角）对冲。

## 3. 模式声明（模式层骨架）

- phase 枚举与归属（core 的 phase 严格 per-worker，故先声明归属再列阶段）：
  - **supervisor 侧阶段（不占 `workers[].phase`）**：`ingest`（材料盘点：输入=PR diff / 文档路径 / 口述+文件混合；PR 场景解析为 diff+涉及文件清单+关联上下文。非 git 输入允许，与 abstract 同）；`assign`（视角规划与 worker 数推荐（§4），在 worker 注册前进行，产出视角分配表——每路视角+其审查清单+明确排除项，经用户裁决后随初始指令下发）；`merge`（全部 worker done 后监工侧合并，出报告）。
  - **worker 侧阶段（占 `workers[].phase`，per-worker 流转）**：`round1`（独立审：只见自己的视角指令与材料，产出 findings（每条：观点+锚点+置信+证伪判据），**互不可见**，隔离机制见下）→ `cross-1` →（必要时）`cross-2` → `done`（cross 完毕即 done，merge 由监工做）。cross 是 core 「该 phase 明确需要汇合」例外条款的适用者：先行者上报 cross-1 回应后 phase 停在原处等待其余方，监工收齐并集再统一下发；worker 侧阶段命名沿用 abstract refine-N 的 N 后缀惯例。
  - **round1 隔离的结构保证**（消息拓扑+落盘位置，非 prompt 约定）：findings 只在 WORKER REPORT 消息体内上报，监工收到后写入**自己的分片账本**（`.supervisor/<sid>/`，PreToolUse 守卫已阻止 worker 写入他人分片）；worker 不得将 findings 作为共享路径文件落盘，round1 阶段产出物就是消息体本身。交叉材料由监工在下发 cross 指令时携带（匿名化并集），不落共享文件。残余边界：worker 若恶意读监工分片文件技术上可行（读不被守卫拦），但协议无激励且报告标注该边界——隔离目标是「不因正常执行而泄漏」，不是防恶意 worker。
  - **cross 交叉攻击**（cross-1 为强制轮，cross-2 为争议复辩轮）：每方收到全部其他方 findings 的并集（匿名化，不含视角署名——防权威跟随），必须逐条回应：反驳（附反证锚点）/确认（升级置信）/撤回（说明原因）。允许新增（攻击过程中发现的新问题）。cross-2 的攻击对象=cross-1 收到的回应，触发条件=存在未收敛争议项；cross-2 新增的 findings 不再强制对抗，merge 时标注「未经交叉」。
  - **merge 收敛判据**：参与过 cross 的 findings 必须处于「至少两路独立一致（单方主张且回应中显式无异议视同一致；无回应不算）/ 单方坚持且经攻防 / 明确撤回」三态之一（视角数无关表述，N 路适用）；「未经交叉」（cross-2 新增）与「因减员未交叉」（见 §7）是三态之外的显式标注态，不参与收敛判定，在报告中单独呈现。未收敛项（各方各执一词且都有锚点）→ 标记为「用户裁决项」带入报告，不无限加轮（Loop Guard：cross 最多 2 轮，仍僵持即止，交用户）。
- 单 worker 降级时 worker 侧阶段为 `round1|done`（cross 无对手，跳过）。
- registry 注册 `--mode adversarial`。
- `--out <报告目录>`：默认 `docs/adversarial/<日期-主题>/`，缺省时 assign 定题后下发（沿用 abstract 的落点纪律）。
- 报告结构：TL;DR（按严重度排序的确认发现）/ 争议项（各方论点+锚点并列，供用户裁决）/ 撤回记录（审查过程可信度的自证）/ 覆盖对账（材料×视角矩阵）/ 视角清单（含各自排除项）。

## 4. worker 数量推荐（assign 阶段决策表）

| 材料特征 | 推荐 | 说明 |
|---|---|---|
| <300 行 diff、单模块、无并发/安全面 | 1（多视角切换） | 降级路径：单 worker 单上下文按清单逐视角扫，省 N 倍材料重读；supervisor 在报告如实标注「未隔离审查」 |
| 中型 PR / 单主题方案文档 | 2 | 实施者视角 + 唱反调视角；性价比拐点 |
| 跨模块 / 架构决策 / 并发敏感 | 3-4 | +安全 / 性能 / 业务语义，按材料裁剪 |
| 涉钱 / 数据迁移 / 大 PR（>2000 行） | 4-6 | 每 1000 行 diff 至少 2 路才能保持单路上下文余量；>5000 行建议先拆 PR 再审（超过 6 路的协调成本反噬对抗质量） |

规则之外：首次推荐附带理由清单（「建议 3 路：涉及模块 4 个、含并发面」）；用户可 ±1，但并发/安全面材料低于 2 路时 supervisor 必须警告；历史数据增强（registry 记录历次「视角×发现分布」，若干次后推荐从规则变有据）为 v2，本期不做。

**推荐交互形态**：assign 的产出不是数字是**视角菜单**——每条候选一行：视角名 + 审查清单 + 排除项 + 入选理由（「架构一致性：涉及模块 4 个，跨模块接口改动占比 60%」）。菜单之外附**备选区**：本材料不必须、但用户可能关心的视角，各配一句话理由（「性能：非热点路径，默认不上」）——用户勾选备选即转正，成本最低的补充入口。用户对着菜单可：全收（默认）、勾掉、勾备选、自造新视角（补入分配表）。裁决通过即 assign 定稿，锁定纪律见「用户补充视角」。

**用户补充视角**：用户在交代任务时点名的视角（如「重点看安全」「加一路合规」）是硬约束——推荐表必须原样收录并标注「用户指定」，决策表的裁剪规则只能作用于监工自荐的视角，不得删除、不得合并用户指定视角。用户在 assign 裁决环节仍可增删改视角（增：补入分配表；删：标「用户移除」记入报告视角清单，防有人事后问「怎么没审这块」）。assign 定稿后视角锁定（与被审对象锁死同款纪律）：flow 进行中要加视角只能重跑（round1 已产出会污染新视角独立性，无法增量补录）；若新增诉求在 round1 结束后才提出，监工将新视角诉求作为单路补充审查独立跑一次，结果单独成节、不合并进已收敛的三态（未经过完整对抗）。

## 5. 复用与新增

**直接复用**：core 全套（五层中断防御/分片账本/OODA/QUESTIONS）——但注意 core 的 `--mode <greenfield|rework|research|abstract>` 枚举行需由本模式层显式替换（拼接产物层面，registry.py 本身接受任意 mode 字符串，无工具侧阻塞）；research 的证据五级与监工抽查（A-C 级发现监工亲自打开锚点复现）复用，但「伪证撤回该视角全部 findings 并整轮重审」是本模式的**新增增强**（research 原判是伪证→该章整体 REFINE，本模式因单视角 findings 量小改为整视角重审）；abstract 的空话检查（每条 finding 自问「证伪会看到什么」）也复用；输入面锁死复用但**锁死对象不同**：abstract 锁提炼输入（不引新材料），本模式锁**被审对象**——ingest 定稿的 diff 版本/文档清单不得中途更换（材料一改锚点全失效）。审 PR 必须读 diff 之外的仓库代码才能判断影响面，故 worker 读上下文自由：发现锚点必须落在被审对象内，反驳用的反证锚点允许落关联文件但需标注路径。

**模式层新增**（预计 ~60 行，模式层预算内）：视角分配表 schema、两轮流转规则、匿名交叉协议、merge 收敛判据、Loop Guard 适配（cross 两轮上限）、worker 数推荐决策表、报告结构。

**worker 协议零改动**：视角以 scope 形式下发（复用 `workers[].scope`），worker 只需照常「干自己的 phase、上报」——它不知道自己在参加对抗。

## 6. 验收（DoD）

1. 真机冒烟：本仓一个真实 merge commit（>300 行）跑通全链路，2 路视角（架构+唱反调），验证：视角隔离（round1 两路 findings 零互相引用痕迹）、交叉回应三态覆盖（至少 1 条反驳+1 条确认+1 条撤回或如实标注未出现）、锚点抽查执行记录、报告五节齐全。N≥3 的合并语义（并集下发+至少两路一致判定）以二次冒烟或桌面演练覆盖，条件不允许则在报告中如实标注未验证。
2. 降级路径：小 diff 单 worker 多视角跑通，报告含「未隔离审查」标注。
3. 三套既有回归测试全绿（零回归）；无锚点 finding 的处理路径（REFINE 打回补锚点，两次不补则撤回该 finding）在冒烟中至少出现一次或如实标注未出现。
4. 拼接产物过结构断言，模式层不与 core 重复标题。
5. 文档：README 四处更新（模式清单/命令表/FAQ 决策树/文件清单）+ 双语（README.md/README-zh.md 同步）+ install.sh 安装完成 echo 块与 README 卸载节中的模式枚举同步，WHY_ME 不动（它是为什么做这套的动机文，不是模式清单）。

## 7. 风险与开放问题

- **cross 轮的匿名性边界**：匿名化防权威跟随，但写作风格可能泄露视角身份——接受（防的是内容跟随不是完全盲审），报告如实标注该边界。另：N=2 时匿名化无实际隐藏作用（对手只有一人，全量即其人），保留统一协议只为实现简单，此边界如实标注。
- **cross 期间的减员**（参与者锁定）：worker 永久失联走 core 既有 ESCALATE 路径后，剩余 ≥2 路 → 继续流程，缺方未被交叉的 findings 标「因减员未交叉」；剩余 <2 路 → 降级为单路汇总，整份报告标注「对抗结构未成立」，如实呈现已有产出不硬装收敛。
- **PR 场景的基线锚**：审 PR 用 `git diff <base>..head`，与 rework 的范围比对同构；PR 未合并前 worktree 检出方式（本地分支 vs fetch PR ref）实施时定。
- **视角中文/英文术语表**：实施时随模式层定稿，与既有协议措辞风格一致（中文协议正文）。
