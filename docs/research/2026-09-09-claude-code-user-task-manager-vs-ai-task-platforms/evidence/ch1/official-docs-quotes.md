## Remote Control（code.claude.com/docs/en/remote-control）
> "Continue a local Claude Code session from your phone, tablet, or any browser using Remote Control. Works with claude.ai/code and the Claude mobile app."

> "Remote Control connects claude.ai/code or the Claude app for iOS and Android to a Claude Code session running on your machine. Start a task at your desk, then pick it up from your phone on the couch or a browser on another computer."

> "Claude keeps running locally the entire time, so your code execution and filesystem access stay on your machine."

> "the conversation and the progress of subagents and dynamic workflows stay in sync across all connected devices, so you can send messages from your terminal, browser, and phone interchangeably."

**7b-同步 判定的关键原文**：
> "**Repeated permission prompts**: after you answer several permission prompts in a session, an 'Approve tool calls from your phone' notification shows the session URL."
> "When you connect, the device shows any subagents and workflows the session already has running in the background. Stop one of them from the device, and Claude Code stops that task on your machine."
→ 手机回复权限提示/发消息直接驱动**本机正在运行的会话** = 7b-同步官方支持（文档原文级）。

**启动姿势**：
- server 模式 `claude remote-control`（`--name`/`--session-id`/`--spawn worktree`/`--capacity 32` 默认）
- 交互会话 `claude --remote-control` 或既有会话 `/remote-control`（保留当前对话历史）
- `/config` → Enable Remote Control for all sessions（`remoteControlAtStartup: true` 用户级 settings.json）
- 版本门：v2.1.200+（--continue/--session-id）、v2.1.224+（跨机消息）
- 不支持：Bedrock/Vertex/Foundry、自定义 ANTHROPIC_BASE_URL、企业网关

**会话接管/存活语义**：
> "If you resume the conversation in a second terminal while the first one still has Remote Control on, Claude Code prints a notice in the second terminal and leaves Remote Control off there instead of taking the session away from the first."
> "These commands work for about four hours after the server stopped."（server 停止后 4h 内可拉回）
> "While the connection is rebuilding, Claude Code queues messages, permission prompts, and status updates... and delivers them once the connection recovers."（断网排队语义）

## Agent View（code.claude.com/docs/en/agent-view）
> "Agent view, opened with `claude agents`, is one screen for all your background sessions: what's running, what needs your input, and what's done."

**7c 本地对照关键原文**：
> "each row shows the session's name, current activity, and its age"
> "The one-line summary in each row is generated by a Haiku-class model... While a session is actively working, the row text updates at most once every 15 seconds"
> 状态分组: Working(动画)/Needs input(黄)/Idle(灰)/Completed(绿)/Failed(红)/Stopped(灰)
> "Press `Space` on a selected row to open the peek panel... Type a reply and press `Enter` to send it without leaving agent view."
> "When the session asks a question with predefined choices, the peek panel shows them as a numbered list and you can press a number key to pick one."
→ 本机 terminal 内的"任务进度一览 + 需要输入的会话置顶 + peek 回复"——7b-同步的本地 TUI 形态。

**限流原文**：
> "background sessions consume your subscription usage the same as interactive sessions, so running ten agents in parallel uses quota roughly ten times as fast as running one."

> "Dispatch is a persistent conversation with Claude that lives in the Cowork tab. You message Dispatch a task, and it decides how to handle it."

## Memory 层级（code.claude.com/docs/en/memory）
用户级 vs 项目级 CLAUDE.md 载入序（广→窄）：
| Scope | 位置 | 共享范围 |
|---|---|---|
| Managed policy | /Library/Application Support/ClaudeCode/CLAUDE.md | 全机器 |
| **User** | **~/.claude/CLAUDE.md** | **本人全部项目** |
| Project | ./CLAUDE.md 或 ./.claude/CLAUDE.md | 源码控制 |
| Local | ./CLAUDE.local.md | 本人本项目 |
- User-level rules: `~/.claude/rules/`（"apply to every project on your machine"）——用户级扩展点实证
- Auto memory: `~/.claude/projects/<project>/memory/`（MEMORY.md 索引 + 主题文件；首 200 行/25KB 启动载入；**同一 git 仓所有 worktree 共享**；机器本地不跨云）
- "Subagents can also maintain their own auto memory"——subagent 级 memory 也有
- /memory /context 命令可见性检查

## /goal 完成条件（code.claude.com/docs/en/goal）
> "Set a completion condition with /goal and Claude keeps working until it's met, a model judges it impossible, or an error you have to fix clears the goal."
- 机制：每 turn 结束由小快模型（默认 Haiku）评条件，未达→自动开下一 turn；达成/不可能/必须修复的错误→清除
- 三种保活机制对比（官方表）：/goal（条件触发）/ /loop（时间触发）/ Stop hook（turn 结束触发）
- **resume 持久**：> "When you resume a session, Claude Code restores a goal that was still active when the session ended."（turn 计数/计时/token 基线重置）
- 背景 work 在跑时延后评估 + 30min check-in（最多 3 次 idle check-in）
- 会话级作用域（"session-scoped shortcut"），非用户级

## 会话管理（code.claude.com/docs/en/sessions）
- resume 入口表：`claude --continue`（最近）/ `--resume`（picker）/ `--resume <name|id>`（可跨项目查找）/ `/from-pr` / `/resume`
- > "A resumed session restores the conversation along with the state saved in it"——恢复项：历史、模型、agent、权限模式、**active goal**、**未过期 scheduled tasks**（Background Bash/monitor 不恢复）
- /branch 分叉会话；/rename 命名（`claude --resume <name>` 直达）
- transcript 存储：`~/.claude/projects/<project>/<session-id>.jsonl`（内部格式，版本间会变）
- > "claude --resume <session-id> from any directory: Claude Code looks for the ID in the current project directory and its git worktrees first, then in every other project on this machine"——跨项目恢复能力

## 定时任务三层（code.claude.com/docs/en/scheduled-tasks）
官方对比表关键行（Cloud Routines / Desktop scheduled / /loop+Cron）：
- "Requires open session: /loop=Yes 其余 No"；"Persistent across restarts: /loop=Restored on --resume if unexpired 其余 Yes"
- **session-scoped 硬边界**：> "Tasks are session-scoped: they live in the current conversation and stop when you start a new one. Resuming with --resume or --continue brings back any task that hasn't expired"
- **7 天过期**：> "Recurring tasks automatically expire 7 days after creation."
- CronCreate/CronList/CronDelete 工具；每会话上限 50 个任务；jitter 30min；`CLAUDE_CODE_DISABLE_CRON=1` 可全禁
- loop.md 用户级定制点：`~/.claude/loop.md`（user-level，任何项目生效）——用户级扩展点又一实证
- Desktop scheduled tasks：本机、无需开 session、持久
- Routines：云上、`/schedule` CLI 创建、支持 API/GitHub 事件触发
